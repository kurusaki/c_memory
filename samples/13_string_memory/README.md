## #13 文字列の最後には何がある？「\0」をメモリで確認

`"Hello"` は5文字ですが、`char name[] = "Hello";` で作られる配列のサイズは6バイトです。最後の1バイトには何が保存されているのでしょうか？

今回は、文字列をメモリダンプし、文字とASCIIコードの関係、文字列の終わりを表すヌル文字を確認します。さらに、文字列の途中にヌル文字を入れ、表示とメモリの内容がどう変わるかを調べます。

動画リンク：https://youtu.be/j8L0b21zwKU

## この回で学ぶこと

- 文字列をchar型の配列に保存する方法
- 文字とASCIIコードの対応
- 文字列の終わりを表すヌル文字 `\0` の役割
- `"Hello"` の保存に6バイト必要な理由
- メモリダンプで確かめる、配列のサイズと文字列の長さの違い

## サンプルコード

ファイル名：`string_memory.c`

```c
#include <stdio.h>
#include "../mdump.h"

int main(void)
{
    char name[] = "Hello";

    /* 終端のヌル文字も含めて、配列全体を確認する。 */
    printf("name = %s\n", name);
    printf("sizeof(name) = %zu\n", sizeof(name));
    mdump(name, sizeof(name));

    /* 3番目の要素を書き換え、文字列の終わりを途中に移す。 */
    name[2] = '\0';

    printf("\nAfter name[2] = '\\0'\n");
    printf("name = %s\n", name);
    printf("sizeof(name) = %zu\n", sizeof(name));
    mdump(name, sizeof(name));

    return 0;
}
```

前半では初期化直後の配列を確認し、後半では `name[2]` をヌル文字に書き換えます。動画で段階的に説明する2つの処理を、1つのプログラムにまとめています。

## コンパイルと実行

macOSでclangを使用する例です。リポジトリのルート（`c_memory`）から、今回のディレクトリへ移動します。

```sh
cd samples/13_string_memory
```

サンプルと、1つ上のディレクトリにある共通の `mdump.c` を一緒にコンパイルします。

```sh
clang -std=c17 -Wall -Wextra -Wpedantic string_memory.c ../mdump.c -o string_memory
```

続いて、プログラムを実行します。
```sh
./string_memory
```


## 実行結果

```text
name = Hello
sizeof(name) = 6
0x16efb2d64 : 48 65 6C 6C 6F 00                                Hello.

After name[2] = '\0'
name = He
sizeof(name) = 6
0x16efb2d64 : 48 65 00 6C 6F 00                                He.lo.
```

アドレスは一例です。実行環境や実行のたびに変わる場合があります。文字コードの値は、今回のmacOSのようにASCIIと互換性のある環境での結果です。

## 1. nameはchar型の配列

```c
char name[] = "Hello";
```

`name` は、要素の型が `char` の配列です。各要素の大きさは1バイトで、メモリ上に連続して並びます。ここでは要素数を省略しているため、コンパイラが初期化に必要な要素数を決めます。

この初期化では、5文字に加えて終端のヌル文字が格納され、6要素の配列になります。

```text
添字       0     1     2     3     4     5
         +-----+-----+-----+-----+-----+-----+
文字     |  H  |  e  |  l  |  l  |  o  | \0  |
         +-----+-----+-----+-----+-----+-----+
16進数     48    65    6C    6C    6F    00
```

`sizeof(name)` は、この配列全体のサイズをバイト単位で求めます。結果は6で、表示には `size_t` 型に対応する `%zu` を使います。

## 2. 文字は文字コードとして保存される

メモリには、文字の形そのものではなく、文字に対応する数値が保存されています。ASCII（アスキー）は、英字や数字、記号などに数値を割り当てる文字コードです。

```text
文字       H    e    l    l    o
16進数     48   65   6C   6C   6F
10進数     72  101  108  108  111
```

例えば、`H` に対応する値は10進数で72、16進数で48です。メモリダンプの数値部分は16進数なので、`48` と表示されます。右側の `Hello` は、同じデータを文字として表示したものです。

C言語がすべての環境でASCIIを使用すると決めているわけではありません。また、今回はASCIIで表せる英字を扱っています。UTF-8の日本語など、1文字を複数バイトで表す場合もあるため、「すべての文字が1文字1バイト」とは限りません。

## 3. 最後の00はヌル文字

```c
'\0'
```

これは値が0の文字を表し、ヌル文字と呼びます。Cの文字列では、最初のヌル文字が終わりの目印になります。ヌル文字自体は文字列の長さに数えませんが、保存する場所は必要です。

```text
Helloの5文字 ＋ ヌル文字の1バイト ＝ 6バイト
```

数字の文字 `'0'` と、ヌル文字 `'\0'` は別のものです。

```text
'0'   数字の文字「0」 → ASCIIでは16進数の30（10進数の48）
'\0'  ヌル文字       → 値は0
```

ダンプの右側にある `Hello.` の最後の点にも注意してください。共通の `mdump` は、`isprint` で表示可能かを調べ、表示できない文字を `.` に置き換えています。この点は、メモリにピリオドが保存されているという意味ではありません。

## 4. 途中にヌル文字を入れるとどうなる？

```c
name[2] = '\0';
```

配列の添字は0から始まるため、`name[2]` は3番目の要素です。最初の `l` をヌル文字に書き換えると、配列の内容は次のようになります。

```text
添字       0     1     2     3     4     5
         +-----+-----+-----+-----+-----+-----+
文字     |  H  |  e  | \0  |  l  |  o  | \0  |
         +-----+-----+-----+-----+-----+-----+
16進数     48    65    00    6C    6F    00
```

`printf` の `%s` は最初のヌル文字の直前までを表示するので、出力は `He` になります。一方、`mdump(name, sizeof(name))` には表示するサイズとして6を渡しているため、ヌル文字の後ろも含めて6バイトを表示します。

後ろの `l` と `o` は消えていません。最初のヌル文字の位置が変わり、文字列として扱う範囲が短くなったのです。配列のサイズは6バイトのままで、文字列の長さは5から2になります。

なお、結果の見出しを表示するコードの `\\0` は、画面にバックスラッシュと数字の0を表示するための書き方です。配列にヌル文字を代入する `'\0'` とは役割が異なります。

## 5. 配列のサイズと文字列の長さは別

このサンプルの `sizeof(name)` は、文字列の終わりを探しているわけではありません。配列全体のサイズを求めています。そのため、配列の途中を書き換えても結果は6のままです。

```text
初期化直後：配列は6バイト、文字列はHelloの5文字
書き換え後：配列は6バイト、文字列はHeの2文字
```

補足として、`strlen` は最初のヌル文字までのバイト数を、終端を含めずに数える関数です。今回の英字では文字数と一致しますが、UTF-8の日本語などでは見た目の文字数とは一致しません。

終端のヌル文字がない配列を `%s` で表示すると、配列の範囲外を読み取る可能性があり、未定義動作になります。今回のように、終端を含む領域を確保して扱いましょう。

## 自分でも確かめてみよう

1. 初期値の `"Hello"` を `"Hi"` に変え、配列のサイズが3バイトになることを確認してみましょう。この場合、`name[2]` はもともと終端なので、後半の代入を行っても表示は `Hi` のままです。
2. 初期値を `"Hello"` に戻し、書き換える場所を `name[1]` に変えてみましょう。表示は `H` までになり、配列のサイズは6バイトのままです。

## まとめ

- 文字列はchar型の配列に保存できる。
- 今回の英字は、ASCIIコードに対応する数値で保存されている。
- 最初のヌル文字 `'\0'` が文字列の終わりを表す。
- `char name[] = "Hello";` は終端を含む6バイトの配列になる。
- メモリダンプを使うと、表示されない終端文字や、その後ろに残ったデータも確認できる。
