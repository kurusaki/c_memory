## 動画シナリオ

今回は第10回、**「構造体はメモリ上でどう並ぶ？」** について学びます。

前回は、構造体とは **「関連するデータを一つにまとめた新しい型」** であることを学びました。

最後に、「構造体はメモリ上でどのように保存されるのでしょうか？」という話をしました。

今回は、その答えを**実際にメモリを見ながら**確認していきます。

---

### 今回使用する構造体

今回は、こちらの構造体を使います。

```c
struct Person {
    char age;
    int score;
};
```

メンバーは

* age（char型：1バイト）
* score（int型：4バイト）

です。

では、この構造体のサイズは何バイトになると思いますか？

1バイトと4バイトなので、**5バイト**と思うかもしれません。

実際に確認してみましょう。

---

### サンプルプログラム

今回のサンプルプログラムです。

**struct_memory.c**

```c
#include <stdio.h>
#include "../mdump.h"

struct Person {
    char age;
    int score;
};

int main(void)
{
    struct Person person;

    person.age = 20;
    person.score = 100;

    printf("sizeof(Person) = %zu\n", sizeof(struct Person));

    mdump(&person, sizeof(person));

    return 0;
}
```

---

### コンパイルしてみよう

ターミナルで、

```bash
clang struct_memory.c ../mdump.c -o struct_memory
```

を実行します。

今回は　**mdump関数** を使うので、**mdump.c** も一緒にコンパイルしています。

---

### 実行してみよう

続いて、プログラムを実行します。

```bash
./struct_memory
```

すると、次のように表示されました。

```text
sizeof(Person) = 8
0x16d102de4 : 14 00 00 00 64 00 00 00                          ....d...
```

なんと、

構造体のサイズは **5バイトではなく8バイト** になっています。

そして、メモリにも8バイト分のデータが保存されています。

では、残りの3バイトには何が入っているのでしょう？

---

### メモリを見てみよう

図で表すと、このようになっています。

```text
0x16d102de4

┌────┬────┬────┬────┬────┬────┬────┬────┐
│ 14 │ 00 │ 00 │ 00 │ 64 │ 00 │ 00 │ 00 │
├────┼────┼────┼────┼────┼────┼────┼────┤
│ age│ ← パディング → │      score       │
└────┴────┴────┴────┴────┴────┴────┴────┘
 1バイト    3バイト             4バイト
```

一番左の **14** は、`age` に代入した20です。

20を16進数で表すと **0x14** になります。

次の3バイトは **パディング** と呼ばれる領域です。

ここには、プログラムで設定したデータは入っていません。

そして、最後の4バイトが `score` の値です。

100を16進数で表すと **0x64** なので、

リトルエンディアン環境では

```text
64 00 00 00
```

という並びになります。

---

### なぜパディングが入る？

では、なぜパディングが入るのでしょう？

CPUは、4バイト単位や8バイト単位でデータへアクセスする方が高速です。

このように、

**データをアクセスしやすい境界へ配置することを「アライメン（Alignment）**と呼びます。

コンパイラは `score` が4バイト境界から始まるように、自動的に3バイト分の空きを追加します。

この空き領域を **パディング（Padding）** と呼びます。

つまり、

**アライメントを満たすために追加される空き領域が、パディングです。**

---

### sizeofが8になる理由

つまり、構造体のサイズは、メンバーのサイズを単純に足したものではありません。

```
age        1バイト
padding    3バイト
score      4バイト
-------------------
合計       8バイト
```

これが、

```c
sizeof(struct Person)
```

が **8** になる理由です。
