## 1. メモリの5つの役割

```text
実行中のプログラムが使うメモリ
────────────────────────────
プログラム領域：実行する機械語の命令
データ領域    ：初期値を持つ静的なデータ
BSS領域       ：ゼロで始まる静的なデータ
ヒープ領域    ：実行中に動的に確保するデータ
スタック領域  ：関数呼び出しに伴う作業領域
────────────────────────────
※役割を整理した概念図。アドレス順ではありません。
```

ここで扱うのは、実行中のプログラムから見た仮想アドレス空間です。搭載された物理メモリが、この図のように5分割されているという意味ではありません。

また、C言語の規格が、この5つの名前や配置を必須としているわけでもありません。OS・実行形式・コンパイラなどによって配置は異なり、実際には読み取り専用データ、共有ライブラリ、メモリマップされたファイルなどの領域もあります。以下は、一般的な実装を理解するための見取り図です。

### プログラム領域

CPUが実行する機械語の命令を置く領域です。コード領域、テキスト領域とも呼びます。テキストという名前でも、Cのソースコードが文章のまま入っているわけではありません。

例えばmain関数の処理は、コンパイルによって機械語の命令になります。命令を保存する場所と、変数の値を保存する場所は区別します。一般的には、コードは通常の変数のように書き換えられないよう保護されています。

### データ領域

グローバル変数やstatic変数など、静的記憶域期間を持つオブジェクトのうち、ゼロではない初期値を持つデータなどが置かれる領域です。静的記憶域期間とは、プログラムの実行中ずっと保存場所が存在する性質です。

今回の `global_value = 100` と `static_value = 200` は、代表的にはこの領域に対応します。これは、main関数の中で実行する代入ではなく、変数の初期値の指定です。

### BSS領域

ゼロで始められる静的なデータを置く領域です。今回の `global_zero` と `static_zero` は初期値を明示していませんが、int型の静的な変数なので、最初の値は0です。

BSSでは、大量のゼロを実行ファイルにそのまま記録する代わりに、必要な大きさを記録し、実行時にゼロの領域を用意できます。明示的に0で初期化した静的な変数も、BSSに置かれることがあります。

「初期値を書いたら必ずデータ領域」「初期値を書かなければすべてBSS」とは限りません。特に、初期化していない普通のローカル変数が自動的に0になるわけではありません。

### ヒープ領域

実行中に必要なメモリを動的に確保するために使われる領域を、一般にヒープと呼びます。今回のサンプルではmallocで確保します。

mallocが返す領域は、呼び出した関数から戻るだけでは解放されません。使い終わったらfreeで解放します。また、mallocで確保した直後の内容がゼロになる保証はないため、値を設定してから読み取ります。

実装によっては、メモリ管理機構が複数の領域を使います。ヒープが必ず1つの連続した領域で、決まった方向へ伸びるとは考えないようにしましょう。

### スタック領域

関数呼び出しに伴う作業場所です。一般的な実装では、普通のローカル変数や関数から戻るための情報などに使われます。

今回の `local_value` とポインタ変数 `heap_ptr` 自身は、main関数の自動変数です。このような変数は、属するブロックの実行が終わると寿命が終わります。寿命を終えた変数へ、保存しておいたポインタからアクセスしてはいけません。

ただし、普通のローカル変数が必ずメモリ上のスタックに存在するわけではありません。最適化によってレジスタで扱われたり、保存場所が不要になったりする場合があります。

## 2. サンプルプログラム

ファイル名：`memory_layout.c`

```c
#include <stdio.h>
#include <stdlib.h>

int global_value = 100;
int global_zero;

int main(void)
{
    static int static_value = 200;
    static int static_zero;
    int local_value = 300;
    int *heap_ptr = malloc(sizeof *heap_ptr);

    if (heap_ptr == NULL) {
        fprintf(stderr, "Memory allocation failed.\n");
        return 1;
    }

    *heap_ptr = 400;

    printf("global_value : %p, value = %d\n",
           (void *)&global_value, global_value);
    printf("static_value : %p, value = %d\n",
           (void *)&static_value, static_value);
    printf("global_zero  : %p, value = %d\n",
           (void *)&global_zero, global_zero);
    printf("static_zero  : %p, value = %d\n",
           (void *)&static_zero, static_zero);
    printf("local_value  : %p, value = %d\n",
           (void *)&local_value, local_value);
    printf("heap_ptr     : %p, value = %d\n",
           (void *)heap_ptr, *heap_ptr);
    printf("&heap_ptr    : %p\n", (void *)&heap_ptr);

    free(heap_ptr);
    return 0;
}
```

### グローバル変数とstatic変数

関数の外に宣言したglobal_valueとglobal_zeroは、どちらも静的記憶域期間を持ちます。main関数の中にあるstatic_valueとstatic_zeroも同じです。

static変数は関数の中で宣言されていても、普通のローカル変数のように関数から戻るたびに寿命が終わるわけではありません。関数を繰り返し呼んでも保存場所が存在し、値を保持します。

変数名をどこから使えるかという「スコープ」と、保存場所がいつまで存在するかという「記憶域期間」は別の性質です。

### mallocでint型1つ分を確保する

ファイル名：`memory_layout.c`（抜粋）

```c
int *heap_ptr = malloc(sizeof *heap_ptr);
```

`sizeof *heap_ptr` は、heap_ptrが指す型、つまりint型のサイズを求めます。この例のsizeofでは `*heap_ptr` の値を実際に読み取るわけではありません。まだ確保できていないメモリにアクセスしているわけではないので、この書き方で必要なサイズを指定できます。

mallocは失敗するとヌルポインタを返します。そのため、NULLかどうかを確認し、失敗した場合はメッセージを出して終了します。成功した後で `*heap_ptr = 400;` として、確保した領域へ値を保存します。

### アドレスと値を表示する

変数自身のアドレスには `&` を付けます。`%p` はポインタを表示する書式で、対応する引数は `(void *)` に変換して渡しています。

heap_ptrの行だけは、ポインタ値heap_ptrと、その指し先の値 `*heap_ptr` を表示しています。その次の `&heap_ptr` の行で、ポインタ変数自身のアドレスを表示します。

最後の `free(heap_ptr)` は、mallocで確保した領域を解放します。解放後の領域にはアクセスせず、プログラムを終了します。

## 3. コンパイルと実行

macOS・clangでの例です。リポジトリのルート（`c_memory`）から移動します。

```sh
cd samples/15_memory_layout
```

コンパイルします。

```sh
clang -std=c17 -O0 -Wall -Wextra -Wpedantic memory_layout.c -o memory_layout
```

`-O0` は、英字のOと数字の0です。今回は配置を観察するため、最適化を抑えます。ただし、この指定でもメモリの順序やアドレスが固定されるわけではありません。

実行します。

```sh
./memory_layout
```

実行結果の例：

```text
global_value : 0x102210000, value = 100
static_value : 0x102210004, value = 200
global_zero  : 0x10221000c, value = 0
static_zero  : 0x102210008, value = 0
local_value  : 0x16dbf6d58, value = 300
heap_ptr     : 0x1027bda40, value = 400
&heap_ptr    : 0x16dbf6d50
```

アドレスや変数の配置順は、OS、コンパイラ、実行条件などによって変わります。アドレス空間配置のランダム化（ASLR）などにより、同じプログラムでも実行のたびにアドレスが変わる場合があります。上記の数字を固定値として覚える必要はありません。

## 4. 実行結果を読む

### 初期値とゼロ初期化

global_valueとstatic_valueには、それぞれ指定した100と200が入っています。global_zeroとstatic_zeroは、初期値を明示していなくても0でした。

一方、local_valueには初期値300を指定しています。普通の自動変数の初期化を省略しても、同じように0になるとは限りません。値を代入せずに表示する実験は行わないでください。

### アドレスの近さから分かること

今回の出力では、グローバル変数とstatic変数が近い位置にあり、普通のローカル変数や動的に確保した領域は別の場所にあります。

ただし、アドレスの数字だけで「ここからここまでがデータ領域」と断定することはできません。変数の宣言順とメモリ上の順番も、必ずしも同じにはなりません。

このサンプルは、異なる性質のデータの値とアドレスを比較するものです。領域の正式な名前、境界、保護属性は、OSのメモリマップや実行ファイルの情報と照合して確認します。プログラム領域の機械語や、その境界を直接表示するプログラムではありません。

macOSではMach-O実行形式のセグメント・セクション情報や、プロセスの仮想メモリ情報が調査の手掛かりになります。例えばAppleの資料では、機械語を置く `__TEXT,__text`、初期値を持つデータの `__DATA,__data`、ゼロで始まるデータの `__DATA,__bss` などが説明されています。実際の名前や構成はツールチェーンによって変わるため、概念図と完全に同じ区切りだとは考えないようにします。

## 5. ポインタ変数自身と、動的に確保した領域は別

```text
一般的な実装でのイメージ

スタック側のポインタ変数        動的に確保した領域
+------------------+          +---------+
| アドレス         | -------> |   400   |
+------------------+          +---------+
     &heap_ptr                    heap_ptr
```

heap_ptr自身はmain関数の普通のローカル変数です。今回のような実装ではスタック側に置かれ、その中に動的に確保した領域のアドレスが入ります。

つまり、「ヒープを指すポインタだから、ポインタ変数自身もヒープにある」というわけではありません。前回の文字列と同じく、変数自身とその指し先を分けて考えます。

freeで解放するのも、ポインタ変数自身ではなく、mallocで確保した指し先の領域です。また、freeを呼んでもポインタ変数へ自動的にNULLが代入されるわけではありません。今回のサンプルは解放後のポインタ値を使用しません。

## 6. 前回のchar配列とcharポインタはどこに置かれる？

前回のコードを、main関数内の宣言として振り返ります。

ファイル名：`../14_char_array_pointer/array_pointer.c`（抜粋）

```c
char name[] = "Hello";
const char *ptr = "Hello";
```

通常の実装では、配列nameとポインタ変数ptr自身はスタック側に置かれます。一方、ptrが指す文字列リテラルは、一般に読み取り専用の領域に置かれます。

文字列リテラルの保存場所は、普通のローカル配列と違い、プログラムの実行中ずっと存在します。ただし、配置先やOSによる保護の有無にかかわらず、C言語では文字列リテラルの変更は未定義動作です。

この例からも、5領域の図が厳密な全領域の一覧ではなく、役割を理解するための整理だと分かります。

## 理解度チェック

1. main関数の中で宣言したstatic_valueは、普通のローカル変数と同じ期間だけ存在するのでしょうか。
2. global_zeroは初期値を省略しているのに、なぜ0と表示されるのでしょうか。
3. heap_ptrと `&heap_ptr` は、それぞれ何の場所を表しますか。
4. `free(heap_ptr)` はポインタ変数heap_ptr自身を解放する操作でしょうか。

### 解答

1. いいえ。static_valueには静的記憶域期間があり、プログラムの実行中ずっと保存場所が存在します。宣言場所と寿命は分けて考えます。
2. 静的記憶域期間を持つint型の変数なので、初期値を明示しなくても0で初期化されます。普通の自動変数について同じことは言えません。
3. heap_ptrはmallocで確保した領域の先頭を指します。`&heap_ptr` は、そのアドレスを保存するポインタ変数自身の場所です。
4. いいえ。mallocで確保した指し先の領域を解放します。ローカルなポインタ変数自身の寿命がfreeによって終わるわけではありません。

## まとめ

- プログラムの命令と、変数の値には異なる保存の役割がある。
- 静的なデータには、初期値を持つデータ領域や、ゼロで始まるBSS領域が関係する。
- スタックは関数呼び出しの作業場所、ヒープは動的に確保するメモリとして使われる。
- 関数の中で宣言した変数でも、staticの有無で記憶域期間が変わる。
- ポインタ変数自身と、ポインタが指す領域は区別する。
- 5領域の図は概念図であり、実際の配置や名前は環境に依存する。
